已知边界：姿态突变不接力；Agnes 503 仍会降级纯文生图，但现在会显式标红而不是静默成功。

---

结论先行（调研时）：

1. **关键帧没按形象生成不是偶发，是代码里的显式策略**：多人镜头在没有同组人上一帧时，会把角色参考图**整块丢掉**；有上一帧时又会**只留上一帧**。项目 45 的 12 张关键帧里有 4 张零参考图。
2. **一次性全量出图没有审核闸门**：拆解弹窗默认勾选「顺带生成图片」，定妆照和整集关键帧会一路串行跑完，中途不能停。行业做法是「定妆照确认 → 试拍一镜 → 分批出图」。
3. **提示词长度确实偏长**：正文只有 120-209 字，但最终图片提示词 669-892 字（上限 900），视频历史上撞满 2000 字。教程里的图生视频提示词只写「画面怎么变」，通常是短结构化文本。

## 二、行业做法（公开教程与工具文档）

以下是公开教程/文章里的共性结论，不是我们自己的推测：

1. **先定妆，再冻结关键帧，最后才动起来**：角色卡 → 正面/侧面/半身参考图 → 关键帧；关键帧定下人物、站位、道具、光线，视频只负责运动。
   - https://m.163.com/dy/article/L951MAIU0556PBKX.html
   - https://g.pconline.com.cn/x/2182/21823006.html
2. **同一个人跨镜必须靠参考图，不靠文字**：文字描述只影响概率，锁不住五官；资产图/参考图是行业通用起点。
   - https://developer.cloud.tencent.com/article/2756692
3. **多人同框先合成「合影剧照」**：两个角色分别处理好静帧，再合成到同一画面，确认长相和位置无误后，才拿这张图去生成视频。
   - https://blog.csdn.net/weixin_33708633/article/details/166664779
4. **多人画面必须加防分身约束**：末尾写「全程禁止出现外形、着装、配饰完全一致的人物，禁止同款分身、双胞胎效果」。
   - https://developer.cloud.tencent.com/article/2755986
   - https://m.toutiao.com/article/7691534597959500331/
5. **图生视频提示词只写「怎么动」**：主体 + 运动；不要重复描述整张图；一镜一种运镜，动作低缓连续；少堆形容词。
   - https://blog.csdn.net/qq_28880087/article/details/168455552
   - https://news.mydrivers.com/1/1152/1152245.htm
6. **提示词模板是字段化的，不是小作文**：景别 / 人物 / 动作 / 表情 / 环境 / 光线 / 运镜 / 时长，一镜一议。
   - https://blog.csdn.net/weixin_29039773/article/details/165902772
   - https://blog.csdn.net/weixin_42554042/article/details/167112873
7. **批量生产要有集中检查点**：静帧阶段集中检查一致性，确认后再批量进视频；不是边生成边放飞。
   - https://blog.csdn.net/weixin_33708633/article/details/166664779

说明：B 站/抖音原视频无法直接抓取全文，以上为同主题教程文章与视频页摘要；结论已交叉核对，不依赖单一来源。

## 三、我们提示词的实际情况

- 图片最终长度：669-892 字（12 张），正文 `prompt_clean` 只有 120-209 字。
- 图片硬上限：`MAX_IMAGE_PROMPT_CHARS = 900`（`prompts.py:1379`）。
- 视频硬上限：`MAX_VIDEO_PROMPT_CHARS = 1400`（`prompts.py:1375`），厂商上限 2000。
- 旧视频提示词实测 1815-2000 字（media 214/219/229/230，项目 34），已经撞满厂商上限；当前虽降到 1400，仍是「贴顶运行」。
- 分层顺序：正文 → 风格 → 主体 → 图例 → 场景状态 → 镜头语言 → 时间轴 → 附加 → 资产 → 画质 → 衔接 → 人数校验 → 负面词（`prompts.py:1505-1576`）。
- 问题不在某一段写错，而在**总预算被十几层重复信息吃掉**：外观、场景、画质、负面词在参考图已经生效时仍是纯重复。

## 四、改造建议（按优先级）

### P0 先修一致性（不改提示词长度也能立刻见效）

1. **多人镜头恢复角色参考**（`generation.py:1960-1972`）
   - 短期验证：允许 2-3 人镜头送多张定妆照，提示词逐图点名「图1=杨间，图2=张伟」，并加防分身句；在自测项目 34 跑 3-5 张统计分身率。
   - 若分身仍高，转「合影主参考」：按「场景 + 演员组合」生成一张同框剧照，人工确认后作为该组合唯一参考（新增 cast 参考表），后续镜头用它 + continuity 链。
2. **上一帧不再覆盖全部角色参考**（`generation.py:1950-1953`）：改为「上一帧 + 本镜新增角色定妆照」，最多 3 张；记录上一帧来源，方便追错。
3. **参考图状态透出到前端**：每张关键帧显示「已用：角色杨间 / 道具手机」或红标「未用角色参考（多人规则 / 队列降级 / 缺公网地址）」。
4. **降级不再算成功**：`reference_used=false` 且本镜有角色主体时，任务结果标记 degraded，前端红色提示并给「强制带参考重绘」。
5. **共享演员兜底**：`_load_shot_assets` 找不到项目内资产时，再查 `project_id IS NULL / is_global` 的演员（与 `load_shared_actors` 一致）。

### P1 分批确认（解决「一次全错、全部重做」）

1. 拆解自动出图拆成两段：
   - 第一段只出**角色定妆照**，完成后暂停；用户在资产页确认、重绘或换图。
   - 第二段先生成 **1 个试拍镜头**（优先选多人同框），确认后再放行下一批（每批 3-5 镜）。
2. `auto_images` 默认改为 **false**（当前 `ProjectDetailPage.tsx:343` 默认 true）；弹窗里改成「生成定妆照后暂停」。
3. 关键帧新增「已认可」状态（`shot_keyframes.approved_at`），批量视频只处理已认可的关键帧。
4. 重绘一帧后，把依赖它做 continuity 的后续镜头标脏，前端提示「参考已变更，需重跑」，避免旧链继续传播错脸。

### P2 提示词瘦身与模板

1. 图片：正文 150-220 字；最终目标 450-600 字，硬上限降到 700；参考图生效时去掉重复外观段。
2. 视频：只写「动作变化 + 运镜 + 不新增人物/不换场」，目标 250-500 字；外观/场景/画质交给首帧。
3. 结构化模板（结合教程与我们的字段）：
   ```
   【参考】图1=杨间（只取五官、发型）；图2=张伟（只取五官、发型）。
   【画面】中景，高三教室傍晚；杨间坐左侧托腮，张伟坐右侧低头看手机。
   【动作】0-1.5s 杨间放下卷子；1.5-3s 张伟抬头。
   【光线】窗外冷光 + 顶灯暖光。
   【约束】画面中只有这两人；禁止同款分身、双胞胎；不要字幕水印。
   ```
4. 多人镜头统一追加防分身句；按厂商拆模板，不把不支持的能力写进提示词。

## 五、验收口径（只在自测项目 34 / 临时项目做）

- 关键帧 `reference_roles` 含 actor 的比例：群戏镜头从 0/4 提到 ≥ 3/4。
- `reference_used=false` 不再静默：前端能看见原因，且可一键重绘。
- 试拍流程：定妆照完成后必须停；未确认时不产生后续关键帧任务。
- 提示词：图片最终长度中位数 ≤ 600 字；视频 ≤ 800 字，且动作语义不被压缩掉。
- 回归：分段拆解 11 镜仍全落库、0 条「语法瑕疵」日志。

## 六、拍板结果与落地差异

1. 群戏：**多参考 + 防分身**（不新增合影表）。若自测 3-5 张仍有明显分身，再升级合影主参考。
2. 粒度：**逐镜确认**；不设 3 镜/批。
3. 预算：没有直接降到 700/1000。实测图片 700 时 `quality/style` 被裁、900 时 792 字全保留；视频 1062 字全保留。最终取**图片 820 / 视频 1150**，并把 `style`、`quality` 设为不可裁剪，用回归测试锁定。
4. P0 / P1 / P2 全做，已随本次迁移 0010 上线。
